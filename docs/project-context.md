## 서비스와 범위

WAY는 운전자가 지도에서 확정한 픽업 지점에 동승자 한 명이 맞춰 나올 수 있도록 차량 위치와 도착 예정 시간(ETA)을 공유한다. 제출용 시연 계획은 차량 전체 화면과 동승자 웹에서 mock 데이터를 쓰는 방식이었고, 서버의 PT용 MVP는 가상 픽업 연동을 대상으로 한다. [MVP 기능 정의](https://app.notion.com/p/4-MVP-410335044a4480b4a88bf8dd25157f83)

- **차량 앱**은 장소를 검색하고 동승자와 픽업 핀을 확정한다. 픽업 생성 요청에서 확정한 핀의 주소·위도·경도를 `pickupLocation`으로 보낸다. 서버에서 받은 초대 링크를 문자로 보내고, Pleos 내비에서 읽은 차량 위치·ETA를 보고하며, 픽업 지점의 정차를 감지해 대기 시작을 요청한다. [프론트 개발 계획](https://app.notion.com/p/415335044a4480fca79fe6921fba0ea0) · [픽업 생성](https://app.notion.com/p/41a335044a448018a3cad0c414b23257) · [대기 시작](https://app.notion.com/p/41a335044a448095a184f0363eafcc19)
- **동승자 웹**은 문자 링크에서 참여 코드를 읽고, 동승자가 참여를 선택하면 서버에서 교환한다. 동승자는 자신의 위치 공유를 거부해도 픽업 핀과 차량 위치·ETA를 볼 수 있다. [참여 코드 교환](https://app.notion.com/p/417335044a4480bc99c6e9e9013cdbd7) · [실시간 통신](https://app.notion.com/p/418335044a4480feb7aac3878bb41f0f)
- **서버**는 픽업 생성 전 후보 핀의 주정차 규제를 판정하고 주변 규제 구간을 제공한다. 픽업이 생성되면 양쪽의 접근 권한을 확인하고, 같은 픽업의 상태와 필요한 위치 정보를 각 화면에 전달한다. 규제 경고가 있어도 핀을 확정할 수 있다. [주정차 규제 조회](https://app.notion.com/p/417335044a44803c953cebcabc2ede39) · [픽업 조회](https://app.notion.com/p/418335044a4480d29d42cb8bfe00ddc9) · [실시간 통신](https://app.notion.com/p/418335044a4480feb7aac3878bb41f0f)

## 채택한 MVP 결정

- **차량 소유권** — PT용 가상 픽업에서 차량 앱은 Pleos Vehicle SDK로 읽은 값을 `VIN` 헤더로 보낸다. 팀은 시연 대상 VIN을 `vehicle` 테이블의 기본 키인 `vehicle_key`로 사전 등록한다. 차량 권한이 필요한 REST 요청과 WebSocket 연결에서 서버는 헤더의 VIN으로 등록 차량을 조회한다. 픽업 생성 시 조회한 차량을 소유 차량으로 연결하며, 해당 차량의 픽업에만 차량 권한을 허용한다. [차량 식별 ADR](adr/ADR-002-PT에서-VIN만으로-테스트-차량을-식별한다.md) · [픽업 생성](https://app.notion.com/p/41a335044a448018a3cad0c414b23257) · [픽업 조회](https://app.notion.com/p/418335044a4480d29d42cb8bfe00ddc9) · [실시간 통신](https://app.notion.com/p/418335044a4480feb7aac3878bb41f0f)
- **생성과 재시도** — 픽업과 초대 한 건을 한 트랜잭션에서 만든다. 탑승 후 최종 목적지는 선택값이며, 미입력 시 생성 요청에서 생략하거나 `null`을 보내고 조회에서는 `null`을 반환한다. 같은 출발 시도는 `requestId`를 재사용하고 서버는 `(차량 키, requestId)`를 유일하게 관리한다. 재요청 시 기존 `pickupId`를 찾고 메모리에 링크가 있으면 같은 링크를 반환한다. 서버 재시작으로 링크를 복구할 수 없으면 차량 앱에 안내하고 기존 픽업을 정리한 뒤 새로 시작한다. [픽업 생성](https://app.notion.com/p/41a335044a448018a3cad0c414b23257) · [픽업 조회](https://app.notion.com/p/418335044a4480d29d42cb8bfe00ddc9)
- **동승자 세션** — URL의 `#code`는 명시적 참여 요청에서만 교환한다. 최초 교환은 동시에 요청해도 한 번만 성공하고, 서버는 동승자 권한을 서명 토큰으로 확인한다. 사용된 코드로 다시 진입할 때는 그 초대에 대한 유효한 기존 `access_token` 쿠키를 확인한다. [참여 코드 교환](https://app.notion.com/p/417335044a4480bc99c6e9e9013cdbd7) · [동승자 권한 결정](https://app.notion.com/p/41a335044a44806b9045d95ed8347eb2)
- **조회와 실시간 갱신** — REST로 확정 핀·상태·남은 대기 시간을 조회하고, 픽업당 클라이언트별 WebSocket 한 연결로 JSON 메시지를 주고받는다. 양쪽 화면은 차량 앱이 Pleos에서 읽은 ETA와 서버가 동승자 위치에서 픽업 핀까지 계산한 도보 경로를 공유한다. 첫 연결과 재연결 시 `READY`를 받은 뒤 REST로 현재 상태를 조회한다. 전화번호는 서버 메모리에 두고 복구할 수 없으면 조회에서 `null`을 반환한다. 실시간 값과 정차 위치는 메모리나 캐시에 둔다. [픽업 조회](https://app.notion.com/p/418335044a4480d29d42cb8bfe00ddc9) · [실시간 통신](https://app.notion.com/p/418335044a4480feb7aac3878bb41f0f)
- **대기와 완료** — 차량의 첫 대기 시작 요청을 수락할 때 `waitStartTime`에 60초를 더해 공통 종료 시각을 정한다. 재요청과 재조회에서도 그 시각을 사용한다. 조회의 `remainingWaitMs`는 `WAITING`에서 0 이상, `MOVING`에서 `null`이다. 이동 중과 대기 중 모두 완료할 수 있고, 완료 기록은 픽업당 최대 한 건이다. 완료하면 동승자 접근과 위치 전송을 중단하고, 연결된 화면에 종료 이벤트 전송을 시도한 뒤 소켓을 닫는다. [대기 시작](https://app.notion.com/p/41a335044a448095a184f0363eafcc19) · [픽업 조회](https://app.notion.com/p/418335044a4480d29d42cb8bfe00ddc9) · [픽업 완료](https://app.notion.com/p/41a335044a44800bac7add3be8741401) · [실시간 통신](https://app.notion.com/p/418335044a4480feb7aac3878bb41f0f)

## 미정 사항과 명세 확인이 필요한 부분

- **생성·재시도 계약** — 링크를 복구할 수 없을 때 기존 픽업을 정리하는 방법과 요청 키 보관 기간, 초기 ETA 입력 여부는 미정이다. [픽업 생성](https://app.notion.com/p/41a335044a448018a3cad0c414b23257) · [픽업 조회](https://app.notion.com/p/418335044a4480d29d42cb8bfe00ddc9)
- **동승자 권한 구현** — 동시 교환에서 코드 소비를 보장할 구현 방식과 교환 응답이 유실되어 브라우저가 쿠키를 받지 못했을 때의 복구 정책은 미정이다. 실제 WSS 환경에서 동승자 쿠키와 차량의 `VIN` 헤더 전달을 확인해야 한다. [동승자 권한 결정](https://app.notion.com/p/41a335044a44806b9045d95ed8347eb2) · [실시간 통신](https://app.notion.com/p/418335044a4480feb7aac3878bb41f0f)
- **실시간 갱신** — 위치·ETA 갱신 주기와 유효 시간, 도보 경로의 최초 계산·재계산 기준, Pleos ETA 단위와 유효 조건은 연동에서 확인한다. [실시간 통신](https://app.notion.com/p/418335044a4480feb7aac3878bb41f0f)
- **대기 종료와 탑승 확인** — 타이머가 0초가 된 뒤의 상태와 전화 제안 시점, 탑승 판정에 쓸 Pleos 이벤트와 대체 확인 방법을 정해야 한다. 완료 명세는 차량 앱의 요청을 설명하고 헤더에는 동승자 웹도 열거한다. 동승자 웹의 완료 요청 허용 여부와 완료 후 재진입 응답을 확인한다.
