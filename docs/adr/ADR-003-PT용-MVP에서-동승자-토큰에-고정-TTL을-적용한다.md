# ADR-003 · PT용 MVP에서 동승자 토큰에 고정 TTL을 적용한다

- **상태** · 제안
- **날짜** · 2026-11-23
- **제안자** · 이재원
- **태그** · auth, pickup, demo

## 맥락과 문제

동승자는 참여 코드를 처음 교환할 때 `access_token` 쿠키를 받는다. 이후 같은 링크를 열면 해당 초대의 유효한 쿠키로 기존 픽업에 재진입한다. 참여 코드의 `codeExpiresAt`은 최초 교환 기한이고, 발급된 토큰의 만료 시각은 별도로 정한다. [참여 코드 교환 이슈 #13](https://github.com/hyundai-way-team/way-server/issues/13) · [Invitation 엔티티](../../src/main/java/com/hyundai/way/domain/invitation/domain/Invitation.java)

발급 후 30분으로 만료를 고정하면, 픽업이 30분 넘게 진행되는 동안 브라우저를 닫았다 돌아온 동승자는 재진입할 수 없다. 이재원은 시연 범위에서 이 문제를 해결하기 위해 고정 TTL을 늘리는 방향을 제안했다. 실제 운영에서는 픽업에 1시간이 걸릴지 3시간이 걸릴지 사전에 알기 어렵다는 점도 고려했다. [동승자 토큰 수명 검토 대화 · 로컬 Codex](codex://threads/01a20711-794e-7680-8900-33924353996e)

## 결정과 이유

PT용 MVP에서는 시연에서 지원할 가장 긴 픽업 시간에 재접속 여유를 더해 `WAY_PASSENGER_ACCESS_TOKEN_TTL`을 정한다. 만료 시각은 최초 발급 시점에 고정한다. 픽업이 진행 중이고 토큰이 유효하면, 동승자는 기존 쿠키로 같은 픽업에 재진입한다. 시연에 사용할 구체적인 TTL은 시나리오의 예상 소요 시간을 확인한 뒤 정한다.

이 방식은 PT에서 픽업과 재진입을 보여주는 데 집중할 수 있게 한다. 서버는 초대 재진입, REST 픽업 조회, WebSocket 연결과 재연결에서 토큰의 유효성과 픽업 종료 여부를 함께 확인한다. 픽업이 완료되면 토큰의 남은 수명에 관계없이 동승자 접근과 위치 전송을 중단하고, 연결된 소켓을 닫는 기존 정책을 적용한다. [WAY 서버 맥락](../project-context.md#채택한-mvp-결정)

## 검토한 대안

- **30분 고정 TTL을 유지한다.** 구성이 단순하지만, 30분을 넘기는 시연에서 픽업이 진행 중이어도 동승자가 재진입할 수 없다.
- **짧은 TTL의 토큰을 픽업이 진행되는 동안 갱신한다.** 브라우저가 계속 요청을 보내면 세션을 이어갈 수 있다. 브라우저를 닫아둔 사이 토큰이 만료되는 경우까지 지원하려면 다시 권한을 확인하는 절차가 필요해, 시연 단계에서 이 흐름을 구현하는 비용이 크다.

## 영향과 트레이드오프

고정 TTL을 늘리면 시연 중 재진입할 수 있는 시간이 길어진다. 그만큼 아직 종료되지 않은 픽업에서 유출된 토큰이 사용될 수 있는 시간도 늘어나므로, TTL은 시연 범위에 맞춰 정한다. 픽업이 고정 TTL보다 오래 진행되면 만료된 토큰으로는 기존 초대에 재진입할 수 없다.

실제 서비스 운영 시에는 짧은 access token과 별도의 갱신 정책을 검토한다. 동승자가 브라우저를 닫아둔 채 토큰 만료 시각을 지나 돌아오는 상황을 기준으로, 갱신 자격과 세션의 최대 유효 기간을 정한다. 운영에서 사용할 TTL과 갱신 방식은 이때 확정한다.

## 검증

2026-11-23 작업 트리의 `application.yaml`에서 환경변수로 TTL을 지정할 수 있고 기본값이 `PT30M`인 점을 확인했다. 시연용 TTL 적용과 아래 동작은 확인이 필요하다. [애플리케이션 설정](../../src/main/resources/application.yaml)

- [ ] 시연의 최장 픽업 시간과 재접속 여유를 반영해 TTL을 정하고, 브라우저가 쿠키를 보유한 상태에서 픽업 완료 전 재진입하면 기존 `pickupId`를 받는지 확인한다.
- [ ] 픽업이 진행 중이어도 토큰 만료 후 초대 재진입이 `403 INVITATION_UNAVAILABLE`로 거절되는지 확인한다.
- [ ] 유효한 토큰이 남아 있어도 픽업 완료 후 초대 재진입, REST 조회, WebSocket 재연결이 거부되고 기존 소켓은 닫히는지 확인한다.
