# ADR-001: 픽업 완료 기록을 pickup 도메인에서 관리한다

- 상태: 채택
- 날짜: 2026-11-19
- 결정자: 이재원
- 태그: domain, pickup

## 맥락과 문제

WAY의 ERD는 픽업과 완료 기록을 각각 `Pickup`, `Completion` 테이블로 표현한다. 완료 기록은 픽업 ID로 식별되고, 픽업당 최대 한 건이다. 완료 행의 존재로 픽업의 `COMPLETED` 상태를 표현할 수 있다. 엔티티를 작성하면서 이 완료 기록의 도메인 소속을 정할 필요가 있었다. [개발일지 · 팀 내부 자료, 접근 권한 필요](https://app.notion.com/p/41d335044a44801c8b72cb46f346eb48)

현재 요구사항에는 이동 중과 대기 중 모두 완료할 수 있다는 규칙, 완료 기록의 중복 생성 방지, 뒤늦은 대기 요청이 완료된 픽업을 되돌리지 않아야 한다는 규칙이 있다. 완료 후에는 동승자 접근과 위치 전송을 종료한다. [WAY 서버 맥락](../project-context.md#채택한-mvp-결정)

## 결정과 이유

`Completion`을 `Pickup`과 같은 `com.hyundai.way.domain.pickup.domain`에 둔다. 적용 범위는 완료 기록 엔티티의 소속과 이를 관리하는 업무 책임이다.

완료 기록은 특정 픽업에 대해 최대 한 건 존재하며 그 픽업의 완료 상태를 나타낸다. 완료할 수 있는 상태, 완료 기록의 중복 방지, 완료 후 대기 요청으로 상태가 되돌아가지 않도록 하는 규칙은 픽업의 상태 전이와 함께 관리해야 한다.

픽업 상태 변경에 대한 트랜잭션과 이 상태 전이 규칙을 `pickup`에서 처리하는 설계에 맞춰, 완료 기록도 이 도메인에 종속시킨다. 이 배치로 상태 변경을 책임지는 업무와 그 완료를 나타내는 기록의 소속을 맞춘다. [원본 논의 · 팀 내부 자료, 접근 권한 필요](https://app.notion.com/p/41d335044a44801c8b72cb46f346eb48)

## 검토한 대안

- **독립 completion 도메인에 둔다.** `Completion`을 `com.hyundai.way.domain.completion.domain`에 배치하는 안이다. 완료 기록을 픽업에 종속시키려는 설계에서 별도 도메인으로 나누면 픽업 상태 변경과 그 완료를 나타내는 기록의 소속이 나뉜다. ERD의 테이블을 코드로 옮길 때 완료 기록의 업무 소속을 우선해 이 안을 기각했다.

## 영향과 트레이드오프

픽업 상태 변경과 완료 기록을 `pickup`이라는 업무 범위에서 함께 관리한다. 패키지 구조에서도 완료 기록이 픽업에 종속된다는 책임을 드러낼 수 있을 것으로 기대한다.

구조상 완료 관련 규칙의 변경도 `pickup`에서 다루게 된다. 완료 업무를 독립적으로 분리하려면 픽업과의 책임 경계를 다시 정리해야 한다. 구체적인 유지보수 비용과 운영 효과는 미확인이다.

## 검증

2026-11-19 코드 확인에서 `Completion`의 `pickup` 패키지 선언과 `pickupId` 기본 키 선언을 확인했다. 2026-11-20에는 같은 패키지에서 `Pickup` 참조와 `@MapsId` 선언, 생성 시 픽업과 연결하는 코드가 있는 것을 확인했다. [Completion 코드](../../src/main/java/com/hyundai/way/domain/pickup/domain/Completion.java)

완료 처리의 트랜잭션과 동시 요청 처리는 미검증 상태다. 아래 항목은 해당 기능 구현 시 확인할 계획이다.

- [x] `Completion`이 `pickup` 패키지에 배치되어 있는지 코드에서 확인했다.
- [ ] 완료 처리 구현 시 이동 중과 대기 중의 완료, 완료 기록 중복 방지, 늦은 대기 요청 처리를 확인한다.
- [ ] 초대 교환과 완료가 경합할 때 완료 후 접근 제한이 지켜지는지 확인한다. 기준 시점과 동시 처리 방식은 구현 단계의 미정 사항이다.
