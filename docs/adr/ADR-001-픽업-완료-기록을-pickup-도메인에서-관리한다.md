# ADR-001: 픽업 완료 기록을 pickup 도메인에서 관리한다

> ⚠️ 이 ADR의 ✍️ 칸은 AI 초안입니다. 면접·리뷰 활용 전 본인 언어로 재작성이 필요합니다.

- 상태: 제안
- 날짜: 2026-11-19
- 결정자: 이재원
- 논의 참여: 이재원, Codex
- 태그: domain, pickup

## 맥락과 문제

WAY의 ERD는 픽업과 완료 기록을 각각 `Pickup`, `Completion` 테이블로 표현한다. 완료 기록은 픽업 ID로 식별되고, 픽업당 최대 한 건이다. 완료 행의 존재로 픽업의 `COMPLETED` 상태를 표현할 수 있다. [개발일지](https://app.notion.com/p/41d335044a44801c8b72cb46f346eb48)

엔티티를 작성하는 과정에서 `Completion`을 독립 도메인 패키지에 두는 안과 `pickup`에 포함하는 안을 검토했다. 이재원은 픽업 상태 변경을 `pickup`에서 처리하는 설계를 근거로 완료 기록도 이 도메인에 종속시키겠다는 의견을 제시했고, 그 판단에 반례가 있는지 검토를 요청했다.

현재 요구사항에는 이동 중과 대기 중 모두 완료할 수 있다는 규칙, 완료 기록의 중복 생성 방지, 뒤늦은 대기 요청이 완료된 픽업을 되돌리지 않아야 한다는 규칙이 있다. 완료 후에는 동승자 접근과 위치 전송을 종료한다. [WAY 서버 맥락](../project-context.md#채택한-mvp-결정)

검토 중 Codex는 픽업과 초대가 한 트랜잭션에서 생성되는 사례를 반례로 제시했다. `Invitation`에는 코드 만료, 최초 교환, 재진입이라는 자체 규칙이 있다. 함께 커밋할 쓰기를 정하는 트랜잭션 경계에 더해, 완료의 허용 조건과 상태 전이를 책임지는 업무도 도메인 소속을 판단하는 기준으로 검토했다. [개발일지](https://app.notion.com/p/41d335044a44801c8b72cb46f346eb48)

## 결정 동인

- 이재원이 제시한 픽업 상태 변경과 완료 기록의 책임을 함께 관리하려는 의도.
- 픽업의 허용 상태, 완료 기록의 유일성, 늦은 대기 요청 처리에 걸친 업무 규칙.
- 테이블 구조를 코드로 옮길 때 엔티티의 업무 소속을 명시할 필요.

## 검토한 선택지

1. **독립 completion 도메인에 둔다.** `Completion`을 `com.hyundai.way.domain.completion.domain`에 배치한다.
2. **pickup 도메인에 포함한다.** `Completion`을 `Pickup`과 같은 `com.hyundai.way.domain.pickup.domain`에 배치한다.

## 결정

`Completion`을 `Pickup`과 같은 `com.hyundai.way.domain.pickup.domain`에 둔다. 픽업 상태 변경에 대한 트랜잭션을 `pickup`에서 처리하는 설계에 맞춰, 완료 기록도 `pickup` 도메인에 종속시킨다.

## 기각한 이유

독립 `completion` 도메인에 두는 안을 기각한다. 완료 기록을 픽업에 종속시키려는 설계에서 별도 도메인으로 나누면, 픽업 상태 변경과 그 완료를 나타내는 기록의 소속이 나뉜다. ERD의 별도 테이블을 코드로 옮길 때도 완료 기록이 픽업에 속한다는 판단을 우선한다.

## 결과

예상되는 결과는 픽업 상태 변경과 완료 기록을 `pickup`이라는 업무 범위에서 함께 관리하는 것이다. 완료 관련 코드를 다룰 때 패키지 구조에서도 픽업에 종속된 책임을 확인할 수 있게 한다.

현재 코드에서는 `Completion`이 `pickup` 패키지에 배치된 것을 확인했다. 완료 처리의 트랜잭션과 동시 요청 처리에 대한 구현·동작 검증은 남아 있다. 운영 효과나 구체적인 유지보수 비용은 아직 확인하지 않았다.

## 검증

2026-11-19 작업 트리에서 `Completion`의 `pickup` 패키지 선언과 `pickupId` 기본 키 선언을 확인했다. 연관관계 매핑은 작성 중이며, 완료 처리의 트랜잭션과 동시 요청 처리는 미검증 상태다.

- [x] `Completion`이 `pickup` 패키지에 배치되어 있는지 코드에서 확인했다.
- [ ] 완료 처리 구현 시 이동 중과 대기 중의 완료, 완료 기록 중복 방지, 늦은 대기 요청 처리를 확인한다.
- [ ] 초대 교환과 완료가 경합할 때 완료 후 접근 제한이 지켜지는지 확인한다. 기준 시점과 동시 처리 방식은 구현 단계의 미정 사항이다.

## 재검토 조건

논의에서 Codex는 탑승 판정이 독립 업무로 커지는 상황을 가정했다. 운영자가 픽업 종료 후에도 증빙 심사, 이의제기, 정정 이력을 관리하고 심사 건에 자체 식별자와 생명주기가 생기면 도메인 경계를 다시 검토할 수 있다. 이 조건은 AI가 제시한 가정이다. [개발일지](https://app.notion.com/p/41d335044a44801c8b72cb46f346eb48)
